# Tutorials

This page provides practical tutorials for using the repository to plan and
build software.

## Tutorial 1: Start A New Software Initiative

### Goal
Turn a rough idea into a structured delivery plan.

### Steps

1. Run [skills/git-sync-first/SKILL.md](../skills/git-sync-first/SKILL.md).
2. Define the use case with [skills/define-use-case/SKILL.md](../skills/define-use-case/SKILL.md).
3. Identify stakeholders with [skills/identify-stakeholders/SKILL.md](../skills/identify-stakeholders/SKILL.md).
4. Define business objectives with [skills/define-business-objectives/SKILL.md](../skills/define-business-objectives/SKILL.md).
5. Create success criteria with [skills/define-success-criteria/SKILL.md](../skills/define-success-criteria/SKILL.md).
6. Draft user stories and workflows.
7. Generate business, functional, system, and data requirements.
8. Assess architecture and create a target design.
9. Build the implementation plan, milestones, and backlog.
10. Run readiness and validation before release.

### Expected Result
You should end with a clear scope, design, delivery plan, and readiness view.

## Tutorial 2: Review A Proposal For Business Approval

### Goal
Evaluate whether a proposal is ready for approval.

### Steps

1. Capture the problem statement.
2. Identify stakeholders and owners.
3. Verify objectives and success criteria.
4. Review the scope and dependencies.
5. Confirm risks and constraints.
6. Check whether architecture and readiness evidence are present.

### Expected Result
You should have a decision, rationale, and list of required follow-up items.

## Tutorial 3: Build An AI Feature Safely

### Goal
Deliver an AI feature with prompt, context, and evaluation discipline.

### Steps

1. Apply [skills/approved-agent-stack/SKILL.md](../skills/approved-agent-stack/SKILL.md) if building an agent solution.
2. Apply [skills/prompt-engineering-best-practices/SKILL.md](../skills/prompt-engineering-best-practices/SKILL.md).
3. Apply [skills/context-engineering-best-practices/SKILL.md](../skills/context-engineering-best-practices/SKILL.md).
4. Apply [skills/harness-engineering-best-practices/SKILL.md](../skills/harness-engineering-best-practices/SKILL.md).
5. Run [skills/perform-readiness-assessment/SKILL.md](../skills/perform-readiness-assessment/SKILL.md).
6. Check risk and production gaps before release.

### Expected Result
The AI feature should have clear prompts, grounded context, evaluation gates,
and release readiness evidence.

## Tutorial 4: Use The Repository As A Business Review Pack

### Goal
Use the repository during a workshop, planning session, or release review.

### Steps

1. Start with the business problem.
2. Select the matching skill from the skill map.
3. Generate a concise output with a decision and next actions.
4. Save the result as part of the project documentation.
5. Revisit the skill if the scope or risk changes.

### Expected Result
Business and technical stakeholders should leave with the same decision,
next step, and accountable owner.

## Tutorial 5: Keep Documentation Current

### Goal
Make sure the repository stays useful over time.

### Steps

1. Update docs when a skill changes.
2. Add examples and test prompts for new skills.
3. Keep README and overview pages aligned.
4. Revalidate skills after major edits.
5. Remove outdated guidance when it no longer reflects how teams work.

### Expected Result
Users can trust the repository as a current source of delivery guidance.

## Recommended Learning Path
